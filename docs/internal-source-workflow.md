# Internal DCS knowledge → safe prompts

Use internal Teams threads, SOPs, and Sentral/OurDCS guides as **design references**, never as copy-paste sources.

1. **Capture metadata only inside the app** — ticket theme, system owner, escalation category, and vocabulary staff actually use.
2. **Rewrite scenarios locally** — fictionalised timelines with privacy-safe language; avoid student/staff names or identifiers.
3. **Cross-check boundaries** — every draft should answer “Would Josh perform this live without approval?” If no, frame as triage + escalation.
4. **Trace back to prompts** — note which internal theme inspired a module (in PR/commit description), not the verbatim wording.
5. **KB Lab packaging** — polish drafts on `/knowledge-base-lab`, run the rubric checklist, then export Markdown into the official publishing channel.
